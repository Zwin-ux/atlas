## 0. Why this exists (the two premises this contract freezes)

Two facts in the current code make an un-specified renderer unbuildable:

1. **The county projection is derived dynamically, per-county, and rescaled
   twice.** `compileCountyGeoScene` computes its origin as the mean of the
   boundary vertices (`cityWorldCountyGeoScene.ts` L182–183), its scale as
   `targetSpanPx / unitSpan` (L228), then runs a *second* land-normalization
   pass that multiplies the scale by a `boost` and re-frames the lattice
   (L346–354). Two packs of the same county with different vertex density, or
   the same pack at a different `targetSpanPx`, land on **different pixels**.
   A chunk addressed against that projection would be non-reproducible. R2
   **MUST** freeze a projection that is a pure function of the pack, computed
   once at bake, and stamped into the pack — never recomputed at render.

2. **The wire already carries packs inline, violating R2's own rule.** The geo
   pack is attached to the `select_county` result `_meta.countyGeoPack`
   (`server/src/index.ts` L3076 loads it, L3093 attaches it). The plan's "R2:
   packs travel only via the pack route, never inflate the widget wire format"
   is therefore not yet true. This is D2-0 (§6).

The chunk indexer that exists today (`cityWorldSceneWindow.ts`) also assigns a
render command to **one** chunk by a single anchor point
(`chunkIdForPoint` L542–546, `getOrCreateChunk` L515–540). A road segment whose
endpoints straddle a cell boundary is filed in exactly one cell; the portion
crossing other cells vanishes. R2 fixes this in §1.4 (eng decision #53).

## 1. Canonical spatial basis (frozen)

### 1.1 Transform ID

The frozen basis is named **`atlas-county-equirect-v1`**. Every pack, manifest,
and chunk **MUST** carry `basisId: "atlas-county-equirect-v1"`. A client that
reads a `basisId` it does not recognize **MUST** refuse the pack and degrade
(§4) — it **MUST NOT** attempt a best-effort render. A new basis is a new ID,
never a silent redefinition of `v1`.

### 1.2 Origin

For each county the bake computes a single reference origin
`originLonLat = [lon0, lat0]` and stamps it into the pack
(`spatialBasis.originLonLat`). The origin **MUST** be the **bounding-box
centre** of the county's LOD0 boundary rings in WGS84 degrees:
`lon0 = (minLon + maxLon) / 2`, `lat0 = (minLat + maxLat) / 2`.

Bounding-box centre, **not** the vertex mean the current code uses (L182–183):
the vertex mean drifts when vertex density changes between re-bakes, which
would move every chunk boundary. The bbox centre is invariant to vertex
resampling. The origin is **frozen at first bake** and carried forward across
re-bakes unchanged unless the county's legal boundary itself changes (a new
Census vintage), in which case the packHash changes anyway (§2).

### 1.3 Units and quantization

The transform maps WGS84 lon/lat to a **county-local metric plane** in metres,
using the same latitude-corrected equirectangular family already in
`toScreen` (`cityWorldCountyGeoScene.ts` L72–78) but in metres against the
frozen origin:

```
E = (lon - lon0) * cos(lat0) * R * (π/180)     // metres east of origin
N = (lat - lat0)            * R * (π/180)     // metres north of origin
R = 6378137                                    // WGS84 equatorial radius, m
```

Coordinates on the wire are **integer quantised** to a fixed step
`Q = 0.1 m` (one quantum = one decimetre): `Ei = round(E / Q)`,
`Ni = round(N / Q)`. Decimetre quantisation is below TIGER/Line's own
positional accuracy, so it loses nothing real while making coordinates small
integers that Brotli compresses hard. `Q` is **frozen** for `v1`.

The renderer maps `(Ei, Ni)` metres back into the existing voxel tile lattice
via the same iso basis it uses today (`CITY_WORLD_TILE_BASIS`,
`unprojectCityWorldGroundPoint`); the metres→tiles scale is a **render-time**
concern owned by the band controller and **MUST NOT** leak into the wire —
the wire is metres, always.

### 1.4 Per-county fixed grid-cell chunk scheme

Chunks are **fixed metric grid cells anchored at the origin** — not
focus-relative, not camera-derived (eng decision #50). Cell edge
`C = 2048 m` for `v1`. A point `(E, N)` falls in cell
`(cellX, cellY) = (floor(E / C), floor(N / C))`. The base chunk id is
`c<cellX>_<cellY>` (signed integers, e.g. `c-3_5`).

Because the grid is a pure function of the frozen basis, the client computes
**which cells** a viewport window intersects with geometry alone, with no
network round-trip. It then resolves those cell ids against the manifest (§2)
to obtain the concrete chunk ids to fetch. The client **MUST NOT** hand-derive
a chunk URL from a cell id; it **MUST** look the cell up in the manifest,
because a dense cell may have been split (below).

**Metro splitter.** A base cell whose serialized chunk would exceed the byte
fail ceiling (§3) **MUST** be subdivided by the bake into quadtree leaves
addressed `c<cellX>_<cellY>_<quadpath>` (e.g. `c12_7_2`, `c12_7_31`), recursing
until every leaf is under ceiling. The manifest enumerates the actual leaves
for a base cell; a cell that split into four is four manifest entries under one
cell key. This keeps the base grid fixed (so decision #34's grid-aligned NEAR
hard-edge stays true) while bounding per-chunk bytes (D2 splitter).

`C = 2048 m` and the split threshold are **frozen-pending-calibration**: they
**MUST** be validated on the adversarial-6 bake (miami-dade-fl, loving-tx,
apache-az, orleans-parish-la, sedgwick-ks, suffolk-ma) and adjusted **once**
before the national bake, after which they are frozen for the packHash lineage.

### 1.5 Clipping, cross-cell features, stable IDs, boundary de-dup

- Every road feature **MUST** be referenced by **every** cell its geometry
  intersects, not only the cell containing an endpoint (eng decision #53 —
  fixes the `chunkIdForPoint` endpoint-only bug, L542–546). The bake **MUST**
  clip each feature to each intersected cell's rect and emit the clipped
  polyline into that cell's chunk, so a chunk is self-contained and its decoded
  size is bounded by its own cell.
- Every feature carries a **stable `featureId`** — the TIGER `LINEARID` where
  present, else a bake-assigned 64-bit hash of the source geometry — **stable
  across re-bakes**. A feature clipped into N cells appears with the *same*
  `featureId` in all N chunks so the renderer can (a) recognise it as one road
  and (b) de-duplicate authored junction/bridge modules that would otherwise
  double-draw where two chunks meet.
- **Boundary de-dup rule:** a vertex lying exactly on a shared cell edge
  belongs to the cell with the **lower `(cellY, cellX)` index** (deterministic
  tie-break); the higher-index cell's clip starts at the boundary crossing.
  This makes the seam reproducible and prevents a doubled edge pixel.

### 1.6 Geometry encoding

`v1` chunk schema is **`roadchunk/1`**: a JSON document (Brotli-compressed on
disk, §3), matching the repo's existing all-JSON client-compile convention
(`data/geo-packs/*.json`). Shape:

```jsonc
{
  "basisId": "atlas-county-equirect-v1",
  "schemaVersion": "roadchunk/1",
  "geoid": "12086",
  "packHash": "b3-9f2c…",          // matches the manifest epoch (§2)
  "chunkId": "c12_7",
  "band": "mid",                    // "lod0" | "mid" | "near"
  "cellRect": [minEi, minNi, maxEi, maxNi],   // quantised metres, inclusive
  "features": [
    {
      "featureId": "1104755807",    // stable across re-bakes
      "roadClass": "S1100",         // TIGER MTFCC, class-tagged at bake (D1)
      "start": [Ei, Ni],            // absolute quantised metres
      "delta": [dEi, dNi, dEi, dNi, …]  // zig-zag deltas from `start`
    }
  ]

  NORMATIVE (ratified with the reference codec, 2026-07-18): "zig-zag" is the
  arithmetic mapping n>=0 ? 2n : -2n-1 applied per delta component — wire
  values are therefore non-negative integers. The arithmetic form (not 32-bit
  bitwise) is required: county spans exceed 2^31 decimetres. Full decision
  record D1–D11 lives in the module header of
  packages/core/src/voxel/roadChunkCodec.ts; roadchunk/2 (binary) must
  re-state its own encoding explicitly.
}
```

Polylines are delta-encoded from an absolute `start` in quantised metres;
deltas are small integers (roads change slowly at 0.1 m resolution) so the
Brotli pass is effective. Junction/ramp/bridge topology is **baked** (eng
decision #60; `collectRoadJoints` is O(n²) at runtime and NEAR-fatal) and rides
as feature `flags`, not computed on the client. A binary encoding is a future
`roadchunk/2` — a **new** `schemaVersion`, never a redefinition of `1`.

### 1.7 Decoded-size limits

Independent of the compressed byte ceiling (§3), a client **MUST** enforce a
**decoded** cap to stop a decompression bomb or a corrupt over-long chunk from
exhausting memory: reject any chunk whose decoded JSON exceeds **2 MB** or whose
`features.length` exceeds **20,000**. A chunk over either cap is an
oversized-decode error (§4), logged and degraded — never partially rendered.
The bake **MUST** guarantee no honestly-produced chunk approaches these caps;
they are a client safety net, not a normal operating point.

## 2. Addressing

### 2.1 The four coordinates

Every chunk is addressed by **GEOID · schemaVersion · packHash · chunkId**
(eng decision #54):

- **GEOID** — the 5-digit Census county id (the county identity; the slug maps
  to it deterministically).
- **schemaVersion** — `roadchunk/1` (the wire shape; §1.6).
- **packHash** — a content hash of the whole county bake output (BLAKE3 of the
  sorted per-chunk hashes). A re-bake that changes any byte changes the
  packHash. Chunk URIs under a packHash are therefore **content-addressed and
  immutable**.
- **chunkId** — `c<cellX>_<cellY>[_<quadpath>]` (§1.4).

### 2.2 Routes

```
GET /road-catalog/<geoid>/current
      → the ATOMIC catalog pointer. Returns { basisId, schemaVersion,
        packHash, manifestUri } for the currently-published epoch, or a
        distinguished 404 (§2.4). MUTABLE, short-cache (§3).

GET /road-chunks/<geoid>/<schemaVersion>/<packHash>/manifest.json
      → the manifest. Enumerates, per band, every cell and its concrete
        chunk id(s), each chunk's compressed byte size and content hash, and
        each chunk's state: "present" | "empty". IMMUTABLE.

GET /road-chunks/<geoid>/<schemaVersion>/<packHash>/<band>/<chunkId>.json
      → one chunk, served precompressed (§3). IMMUTABLE.
```

The manifest **MUST** declare **both** expected-and-non-empty chunks and
**expected-and-empty** cells (a cell inside the county with zero roads of that
band). This is what lets the client tell "sparse but valid" (render nothing,
no status) from "should be here but isn't" (partial failure) — eng decision #62.

### 2.3 Epoch pinning per session

On the first chunk need for a county, the client resolves
`/road-catalog/<geoid>/current` **exactly once** and captures
`{schemaVersion, packHash}` as the **pinned epoch** for that county for the
whole session. Every subsequent manifest and chunk fetch uses the pinned epoch
(eng decision #54, "one manifest epoch pinned per session"). Because chunk URIs
are immutable and old bakes are retained until GC, a re-bake that publishes a
new epoch mid-session **MUST NOT** perturb the client — it keeps rendering the
pinned epoch. Generations are never mixed within a session.

Publish is atomic: a new bake writes its immutable tree, then the catalog
pointer is flipped by **temp-write + rename** (never an in-place edit). A reader
sees either the whole old epoch or the whole new one.

### 2.4 The four distinguished states and their HTTP responses

| State | Meaning | Where | HTTP | Body | Client action |
|-------|---------|-------|------|------|---------------|
| **absent pack** | county has no road bake at all | catalog | **404** | `{state:"absent"}` | LOD0 only; quiet "street detail unavailable" **only** if the user zoomed expecting detail; no retry loop |
| **missing expected chunk** | manifest says present+non-empty, chunk GET finds nothing (the mid-seed partial, eng decision #47) | chunk | **404** | `{state:"missing-expected",chunkId}` | partial-failure path: visible degrade, per-epoch backoff, retry on next gesture — **distinct** from absent pack |
| **retired version** | requested packHash/schemaVersion GC'd | manifest/chunk | **410** | `{state:"retired"}` | drop pinned epoch, re-resolve catalog **once**, rebuild window on the new epoch; degrade if the re-resolve fails |
| **storage failure** | volume unmounted / FS read error / timeout | catalog, manifest, or chunk | **503** | `{state:"storage-unavailable"}` | 1 retry, then visible degrade; per-epoch backoff |

Plus the guard case, unchanged from the platform posture: a malformed
`geoid`/`band`/`chunkId` param is a **400** with a loud server log and **nothing
shown to the user** (the request is hostile, not a user action) — reusing the
slug-guard shape already in `loadCountyGeoPack` (`^[a-z0-9-]+$`, L112) and
extended with a `band` enum (`lod0|mid|near`) and a `chunkId` regex
(`^c-?\d+_-?\d+(_[0-3]+)?$`). Path construction **MUST** use only validated
parts (no traversal), per plan S3.

An **expected-empty** cell is **not** a state above — the client reads it from
the manifest and renders sparse with **no** fetch and **no** status. Sparse ≠
failed (plan Pass 2, status rules).

## 3. Size and serving

### 3.1 Per-chunk byte ceiling

Per chunk, measured on the **compressed on-disk `.br` bytes** (the bytes that
cross egress): **32 KB warn / 64 KB fail** (eng decision #45). The fail ceiling
is a **bake gate** — the bake **MUST** fail (non-zero exit, failure manifest) if
any leaf chunk exceeds 64 KB after the splitter has run (§1.4). The warn ceiling
is a size-ledger signal surfaced in the D3 integrity gate. Both numbers are
**calibrated on the adversarial-6 bake before national** and then frozen for the
lineage; miami-dade-fl is the splitter's proving ground.

### 3.2 Precompressed Brotli static serving

The bake **MUST** write each chunk and manifest precompressed with **Brotli
quality 11** (`.json.br`), plus a gzip fallback (`.json.gz`) and the identity
`.json`. The server **MUST** serve the precompressed bytes directly — it
**MUST NOT** compress per request — using exactly the content-negotiation
already proven for the widget shell: `negotiatePreviewEncoding`
(`server/src/index.ts` L1720–1725) returns `br` → `gzip` → identity from the
request `accept-encoding`, and the response sets `content-encoding` to match
(the pattern at L1735–1749). This reuses the repo's existing
`brotliCompressSync` path (L5, L1709) rather than inventing a new one.

### 3.3 HTTP caching and CORS headers

Chunk and manifest responses are **content-addressed under a packHash → truly
immutable**, so they carry the exact header the repo already applies to
immutable `/chunks/` assets (`sendWidgetAssetResponse` L1762–1765):

```
cache-control: public, max-age=31536000, immutable
vary: accept-encoding
access-control-allow-origin: *              // see §5 — required for the
cross-origin-resource-policy: cross-origin   // web-sandbox cross-origin fetch
content-encoding: br | gzip                  // when negotiated
```

The catalog pointer `/road-catalog/<geoid>/current` is **mutable** (publish
flips it) and therefore **MUST** be `cache-control: no-cache` (or a short
`max-age` under a few seconds), so a fresh session sees a new publish while an
existing pinned session is untouched (§2.3).

Wildcard `access-control-allow-origin: *` is correct here for the same reason
it is correct for the widget bundle (L1766–1772): these are static,
public-domain, read-only geographic bytes with no user data and no credentials.

### 3.4 CDN-swappable thin serving abstraction

D2 serving **MUST** sit behind a thin store interface so the physical backing
(Railway volume today; an object store / CDN origin later) is a config swap, not
a route rewrite (CEO decision #15 — avoid Railway lock-in for CDN-shaped static
geography). The route handler talks only to this interface; it never reads the
filesystem directly.

```ts
// The route depends on this, never on fs or a specific provider.
export interface RoadChunkStore {
  /** Atomic catalog pointer. null → absent pack (→ 404). */
  resolveCurrentEpoch(geoid: string): Promise<CatalogPointer | null>;

  /** Manifest for a pinned epoch. "retired" → 410, "unavailable" → 503. */
  getManifest(
    geoid: string, schemaVersion: string, packHash: string,
  ): Promise<StoreResult<ManifestBytes>>;

  /**
   * One precompressed chunk for a pinned epoch and band.
   * Returns the already-Brotli/gzip/identity bytes plus which encoding they
   * are, so the route sets content-encoding without recompressing.
   * "missing" → 404, "retired" → 410, "unavailable" → 503.
   */
  getChunk(
    geoid: string, schemaVersion: string, packHash: string,
    band: Band, chunkId: string, accept: AcceptEncoding,
  ): Promise<StoreResult<EncodedBytes>>;
}

type Band = "lod0" | "mid" | "near";
type CatalogPointer = { basisId: string; schemaVersion: string; packHash: string; manifestUri: string };
type EncodedBytes = { bytes: Buffer; encoding: "br" | "gzip" | "identity" };
type StoreResult<T> =
  | { ok: true; value: T }
  | { ok: false; reason: "missing" | "retired" | "unavailable" };

// Today: FilesystemRoadChunkStore over the Railway volume, reusing the
// loadCountyGeoPack slug guard + negative cache (server/src/index.ts L109–129).
// Later: ObjectStoreRoadChunkStore (S3/R2/CDN origin) — same interface, config-selected.
```

The `StoreResult.reason` values map one-to-one onto the §2.4 HTTP responses, so
the route is a thin translator and the four distinguished states are enforced in
one place.

### 3.5 Named rate-limit bucket

`/road-chunks` and `/road-catalog` are **static routes that bypass the MCP
tool-call limiter** — without their own bucket a scraper could enumerate
county × band × chunk and pull the whole national bake unthrottled (eng decision
#46). They **MUST** use a **distinct named bucket**, `road_chunks`, via the
existing limiter (`enforceRateLimit(req, res, "road_chunks",
ROAD_CHUNKS_RATE_LIMIT)` → 429, L1996–2015), independent of
`mcp_expensive_tool` (L2027) and `world_lookup` (L202). Suggested ceiling:
**240 requests / 60 s per client** — above the MCP expensive bucket (120)
because one legitimate NEAR pan fetches many chunks, but bounded to defeat
enumeration. The number is **calibration-pending**: it **MUST** be re-checked
against a measured NEAR-pan burst on miami-dade-fl before it is frozen, so a
real pan is never rate-limited into a false degrade. Loopback exemption and the
Redis-or-memory backing come for free from the existing bucket machinery
(L199–205, `consumeRateLimit`).

## 4. Client semantics

### 4.1 All-required-window validation before a single transactional commit

The band controller (the stateful web-side owner; windowFor stays a pure filter
receiving the committed band + immutable epoch — eng decision #56) drives every
transition as **one transaction** (eng decision #58, which **supersedes** the
earlier "visible batched appearance" design #33):

1. Compute the **required chunk set** = cells intersecting the committed window
   for the committed band under the pinned epoch (§1.4, §2.3), minus cells the
   manifest marks empty.
2. Fetch and validate **all** of them **off-stage** (no visible change yet).
3. Build the incoming layer off-stage (CPU-geometry staging preferred so old
   and new Pixi trees do not both go resident — eng decision #59; the 1600
   ceiling includes the transient peak).
4. **Only when every required chunk is decoded-and-valid**, perform **one**
   atomic swap, then release the outgoing layer.

If **any** required chunk fails, there is **no partial commit** — the current
band stays fully interactive and a compact banner-grammar status shows (plan
Pass 2 / status rules). Class priority (highways before locals) governs
**construction order only**, never a visible batch sequence (eng decision #58).

### 4.2 Per-version (per-epoch) failure backoff

Failures are keyed by pinned **packHash**. After a failed required-set fetch the
controller backs off (exponential, capped) before retrying that epoch's window,
and retries are additionally gated to the next gesture-settle. The client
**MUST NOT** retry-hammer a failing epoch (eng decision #62). A `410 retired`
resets state instead of backing off: drop the epoch, re-resolve once (§2.4).

### 4.3 Explicit failure handling (each named)

| Condition | Detection | Handling |
|-----------|-----------|----------|
| **corrupt Brotli** | decompression throws | treat as chunk error → degrade + per-epoch backoff; log; **never** render partial bytes |
| **invalid schema / coords** | `basisId`/`schemaVersion` mismatch, coord outside `cellRect`, NaN/∞ | reject the chunk, error + log, degrade — **MUST NOT** render garbage geometry |
| **oversized decode** | decoded > 2 MB or > 20,000 features (§1.7) | reject, error, log, degrade |
| **stale completion** | a fetch resolves after its window / band / epoch / selection was superseded (latest-wins keyed by scene·place·epoch — eng decisions #57/#7) | **discard silently**; never commit a superseded result |
| **abort** | band change, drill-down, navigate-away, lost capture, blur, unmount | cancel in-flight fetches via `AbortController`; run cancellation cleanup so no orphan Pixi tree survives (eng decision #9) |
| **mid-seed partial** | manifest-expected chunk returns 404 (§2.4) | partial-failure path: visible degrade, per-epoch backoff, retry next gesture — **distinct** from absent-pack (eng decision #47) |

The R2 chunk-fetch loop is a **new trust boundary** — this renderer never
fetched mid-interaction before (eng decision #48) — and therefore gets its own
abort/retry/queue hardening pass and hostile-input tests, not "pattern reuse."

## 5. Host reality (the reason emulator acceptance is not acceptance)

### 5.1 The blocking fact

The widget resource ships **`csp.connectDomains: []`**
(`server/src/index.ts` L2986–2989). In the **real** ChatGPT host the widget
therefore **cannot `fetch()` any backend origin at all** — the chunk route is
unreachable from production today (eng decision #55 / codex-eng #5). `/emulator`
is served **without a restrictive CSP** on purpose (L1670–1674), so it **cannot**
prove the fetch works. Acceptance in the emulator is necessary but **not
sufficient**; R2 acceptance **MUST** run in the real ChatGPT host (cross-phase
theme #3).

### 5.2 What the contract requires the host envelope to carry

- **A single absolute trusted asset origin** for chunks — an HTTPS origin the
  widget is permitted to connect to, configured via the existing
  `WIDGET_DOMAIN` env (already used for `resourceDomains` at L1666, L1694–1696).
  Chunks **SHOULD** be served from that origin (or a dedicated
  `assets.`/CDN subdomain, per the swappable store in §3.4). Relative URLs
  **MUST NOT** be assumed — the widget runs from a sandbox origin, not the
  backend origin.
- **CSP allowlist:** the trusted asset origin **MUST** be added to
  `connectDomains` (today `[]`). `resourceDomains` already carries
  `WIDGET_DOMAIN` for `<script>`/`<img>`, but a `fetch()` is governed by
  `connect-src` → `connectDomains`; without it the fetch is CSP-blocked.
- **CORS:** the chunk origin **MUST** answer the widget's cross-origin fetch
  with `access-control-allow-origin` + `cross-origin-resource-policy:
  cross-origin` — exactly the headers the widget bundle already sends
  (L1771–1772) precisely because real ChatGPT loads the widget from
  `<our-domain-dashed>.web-sandbox.oaiusercontent.com` and fetches
  cross-origin (documented at L1766–1770). Wildcard ACAO is acceptable
  (public, credential-free data).

### 5.3 Owner decision: this change defaults to post-submission

The `connectDomains` change **touches the widget envelope**, i.e. the submitted
surface (P6). Per the plan's APPROVAL gate ("widget CSP change → verify
review-safety, default post-submission-decision") and eng decision #55, this
contract **specifies** the CSP/CORS change but it **does not ship until the
owner clears it post-submission-decision**. Consequences the renderer work must
accept: until the flip, the chunk route is additive and dark, unreachable from
the real host, and real-host acceptance of R2 is **blocked on the flip**. The
emulator carries R development; the real-host gate is deferred to the flip, not
skipped.

## 6. D2-0 — additive route now, `_meta` removal deferred

Today the geo pack is delivered **inline** in `_meta.countyGeoPack`
(`server/src/index.ts` L3076 load via `loadCountyGeoPack`, L3093 attach). That
is the wire already carrying packs (§0). D2-0 (eng decision #41) resolves it in
a **strictly additive, two-step** sequence:

1. **Now:** add the fetchable GET route. It **SHOULD** be the LOD0 band of the
   same addressing (`/road-chunks/<geoid>/lod0/<packHash>/…`) so boundary/water
   packs and road chunks share one epoch, catalog, and cache discipline; a
   simpler sibling `/geo-pack/<slug>` reading the same `data/geo-packs/<slug>.json`
   as `loadCountyGeoPack` (L109–129) is an acceptable D2-0 implementation if the
   shared addressing is not ready. Either way it **MUST** reuse the extracted
   slug-guard + negative-cache helper (plan S5-a), be **flag-dark**, and land
   with its **own regression test**.
2. **Deferred (post-CSP):** remove `_meta.countyGeoPack`. It **MUST NOT** be
   removed until the widget can actually fetch — i.e. after the §5 CSP flip.
   Until then the real host has no other way to obtain the pack, so removing it
   now would blank the real-host board. The route is added now (no behavior
   change; `_meta` still authoritative); the inline delivery is deleted only
   once fetch works, in a follow-up.

This ordering means R renderer work can build against the route in the emulator
immediately, while the real host keeps rendering from `_meta` until the CSP flip
makes the route reachable and the inline copy redundant.

## Appendix B — open questions carried into review

1. **Frozen-pending-calibration constants.** `C = 2048 m`, `Q = 0.1 m`, the
   split threshold, the 2 MB / 20,000-feature decode caps, and the
   `road_chunks` 240/min ceiling are defensible v1 defaults but the plan
   mandates calibration on the adversarial-6 bake before national. They are
   frozen only after that run confirms them.
2. **LOD0 addressing unification.** Whether D2-0 folds county boundary/water
   packs into `band=lod0` of the shared addressing or keeps a separate
   `/geo-pack/<slug>` route is left as an implementation choice (§6); the
   recommendation is unification, but the plan does not force it.
3. **Chunk payload format.** `roadchunk/1` is JSON-quantised to match the
   all-JSON client-compile convention; a binary `roadchunk/2` is anticipated
   but unspecified here.
4. **Production asset-origin identity.** Same-origin backend vs a dedicated
   CDN subdomain is an ops/owner call (only `WIDGET_DOMAIN` exists in code);
   §3.4's swappable store keeps it a config decision.
5. **`featureId` fallback hashing.** Where TIGER `LINEARID` is absent, the
   64-bit geometry hash's exact input (raw vs quantised coords) must be pinned
   so re-bakes stay stable — flagged for the D1 bake spec.
