## Context

Owner picked (2026-07-12): make real geography the next focus, and deploy the
certified backlog now. The county geo compiler (`compileCountyGeoScene`,
committed `c116c1b`, tested) is ORPHANED — nothing in server/web consumes it,
so real county shapes produce zero user-visible output. Wiring it is the
direct answer to the standing critique "the county isn't accurate." Caveat
that shapes the wire: the compiler currently emits ONLY flat grass tiles — so
connecting it as-is renders a featureless green blob. The wire MUST add real
water from the pack (Miami-Dade's bay, Kalawao's sea cliffs) or the first
result is worse than today's generated preview. 0.80 graphics (grade+lighting)
runs in parallel.

   the pack's water polygons; add a shore band at the land/water boundary and
   a board-edge bevel so the silhouette reads land-vs-sea. Deterministic +
   new tests (Miami-Dade has substantial water; Loving ~none).
3. **Wire** — server attaches the county geo pack to the shell-county tool
   result `_meta` (small, same spec-not-scene pattern as 0.76-T); widget
   `web/src/App.tsx` compiles + renders the county board as the PRIMARY county
   view when a pack is present; the generated district demotes to the
   town-detail drill-down (Phase 3).
4. **Gates** — determinism; existing silhouette-fidelity; NEW water-from-pack
   presence check; emulator audit/perf at county scale. The board is
   terrain-heavy (banded, cheap) so likely UNDER the 1600 ceiling — measure;
