# 0.76 — Backend Architecture (going meta on the USA region)

**Purpose:** step back from packets and reason about the system that makes
"every county at the curated bar" (NS-6) actually work — the data model, where
computation lives, the parameter space, and the disciplines it demands. Written
by Opus, 2026-07-07, as the thinking layer under `0.76_USA_REGION_ARCHETYPES.md`.

---

## 1. The one honest input

Everything a county's scene may derive from is one row:

```
NationalCountyIndexEntry = { geoid, stateCode, name, countySlug, centroid{lat,lng} }
```

Plus a deterministic seed = `hash(geoid)`. That is the **entire** honest signal
(NS-4): no provider geometry, no satellite, no population, no real street data
ever reaches the renderer. So the whole visual identity of 3,222 counties must
be a **deterministic pure function of ~5 scalar facts + a seed**. That
constraint is the design problem. It is also the honesty guarantee: a synthetic
scene can never leak real geometry because it never had any.

## 2. The pipeline as it is today

```
county ─▶ selectGeneratedDistrictArchetype ─▶ 1 of 6 buckets
                                               │
        generatedZones / generatedRoadSeeds / generatedHeightGrid(archetype, seed)
                                               │  (hardcoded per bucket + ±jitter)
                                               ▼
                        CityWorldParametricSpec  ──▶ generateParametricCityWorldScene
                                               │
                        CityWorldScene (compiled) ──▶ server ships WHOLE scene on
                                               │       _meta.generatedDraftScene (~780KB)
                                               ▼
                                        widget renders _meta scene
```

**Two diagnoses.** (a) *Identity = bucket + noise.* The only thing separating
two counties in the same archetype is seed jitter, so a CO mountain county and a
VT mountain county are byte-similar. (b) *Transport = whole scene.* The server
compiles and ships the full ~780KB scene; the client consumes it as data. This
is the `_meta` scale watch-item, and it is bigger than it needs to be.

## 3. Reframe — from "6 templates × jitter" to a layered parameter model

The intelligence does not belong in the generator. It belongs in the
**parameter derivation**. The generator should stay a dumb, deterministic
interpreter of a rich parameter object; the art is in composing that object from
the honest input.

```
resolveCountyParameters(county, seed) -> CountyGenerationParameters
   ├─ archetypeProfile   (6)   terrain morphology, zone family, water, landmark
   ├─ regionProfile      (~9)  Census division → palette bias, roof/facade
   │                            vernacular weights, vegetation
   ├─ climateModifier          latitude band (roof pitch, snow, vegetation) +
   │                            aridity proxy from region+longitude (ground tone)
   ├─ nameSignal               lexical hints from the county's OWN name —
   │                            River/Port/Lake/Mesa/Springs/Fort/Falls/Harbor
   └─ seed                     within-envelope jitter (geoid hash)
```

Now identity is **composed, not bucketed.** Two "mountain_valley" counties
diverge because their region (Rockies vs Green Mountains), latitude band, and
name signal differ — without anyone hand-authoring either county. This is the
only known way to get 3,222 *distinct yet coherent* identities from five facts.

`nameSignal` deserves emphasis: it is free, honest (the name is census
identity), and high-signal — "Lake County" getting a water body, "Mesa County" a
dry plateau, "Port ___" a working waterfront. It is the cheapest identity lever
available and currently unused.

## 4. Config-driven, not hardcoded

Today `BASE_HEIGHT_GRIDS`, zone rectangles, and (soon) palettes live as code
inside per-archetype functions. Move them to **typed config tables** —
`ARCHETYPE_PROFILES`, `REGION_PROFILES`, `REGIONAL_PALETTES` — that the generator
reads. Consequences:

- The **config is the reviewable surface.** A designer (me/Fable/user) tunes
  data tables, not control flow — palettes and vernacular become editable
  tokens. This is exactly the "config and parameters" perspective: the product's
  taste lives in data you can diff, screenshot, and gate.
- The generator becomes a small pure function easy to reason about and test.
- New coverage (a 7th archetype, a finer region split) is a data change with a
  gate, not a code fork.

The 0.76-1 packet's flat per-archetype palettes are the **base layer** of
`REGIONAL_PALETTES` — not throwaway. Region/climate layering multiplies on top.

## 5. The scale unlock — ship parameters, not scenes

**Verified today:** `server/src/index.ts:1089` sets
`generatedDraftScene: packet.payload as CityWorldScene` — the server compiles
and transports the full ~780KB scene on `_meta`; `web/src/App.tsx:378` reads
that scene whole. But **`@atlas/core` (the generator) is already in the client
bundle** — the widget can run the same deterministic
`generateParametricCityWorldScene` from the compact
`DeterministicGeneratedDistrictSpec` (zones + roadSeeds + heightGrid + seed —
a few KB).

**Proposal (own gated slice):** ship the **spec**, compile **client-side**.
- `_meta` payload collapses ~100× (KB, not ~780KB) → the scale watch-item
  disappears.
- Honors AGENTS.md: "browser pan/zoom must not wait on Railway," and "should
  not require the transcript to carry giant voxel arrays."
- Preserves honesty: the client runs the identical provider-free pure function;
  it invents nothing the server wouldn't.
- Redis (0.72B) then caches tiny specs, or becomes optional for the draft path;
  server-side compile stays available for hosts that can't run the bundle.
- Cost/care: it changes the tool-result-shape contract (`verify-tool-result-shape`)
  and the widget's ingest path — a real slice with its own verifier, not a
  drive-by. Curated Riverside already renders client-side, so the pattern
  exists.

This is the single highest-leverage backend move for NS-6 scale, and it is
orthogonal to the visual packets — it can run in parallel.

## 6. Parameter envelope & coherence

More parameters → more ways to produce nonsense (a "coastal desert," a snowy
subtropical roof). The model needs **envelope constraints**:
- Valid-combination rules and clamps (aridity suppressed near coast; snow-roof
  gated by latitude band).
- Determinism is a hard contract — every layer seed-threaded, no `Date.now` /
  `Math.random` (they are unavailable in the workflow/gen context by design).
- The distinctness gate should mature from color-set Jaccard (the current
  `verify-archetype-identity-sweep.mjs`, worst-pair 0.886 today) toward
  **perceptual** distance (Lab ΔE on dominant colors) + **silhouette** distance
  (massing/roofline) + **vernacular** distance — identity is more than palette.

## 7. The disciplines this demands (the honest skills list)

| Skill | Why it's load-bearing here |
|---|---|
| Deterministic pure-function design | Reproducibility is verifier-enforced; a scene must be a function of (params, seed) only. |
| Typed contracts at the compiler seam | `CountyGenerationParameters` is the interface the whole model hangs on; renderer consumes compiled output only (0.73F facade contract). |
| Color science | Harmonious *and* distinct palettes across composition; the distinctness metric is Lab, not RGB string compares. |
| Draw-call budgeting | Graphics ≤ 1,600 worst-window is a hard real-time ceiling; every parameter that adds geometry is costed against it. |
| Data engineering | Precompute per-county derived fields (region, climate band, coastal proximity, name signal) offline into the index so the hot path stays ~5ms. |
| Batch/property-based verification | Identity is a claim about a *population* of 3,222; the sweep + property tests are the proof, and "a verifier that cannot fail is not proof." |
| Taste oracle (human-in-loop) | The crop test is the acceptance gate machines can't replace; verifiers catch regressions, Fable/user judge ties. |

## 8. What this changes in the plan

- Treat 0.76-1 palettes as the **base layer** of a config-driven `REGIONAL_PALETTES`
  — author it so region/climate can multiply on top (don't bake flatly).
- Add **0.76-T "Ship parameters, not scenes"** as its own gated transport slice
  (client-side compile from spec), runnable in parallel with the visual packets.
- Add **0.76-P "Parameter model spine"**: `resolveCountyParameters` +
  `CountyGenerationParameters` type + region/climate/name derivation, as the
  substrate levers 1–4 plug into. This is the packet that turns "6 templates"
  into a model.
- Grow the distinctness gate from Jaccard → perceptual + silhouette + vernacular.

## Anti-scope (unchanged)
No provider geometry, no new deps, no persistence/money/new MCP tools/public
Anaheim-Ontario. Honesty (NS-4) is stop-ship. The parameter model derives only
from census identity + seed — it makes the synthesis *richer*, never *truer*.
