# Plan: 0.78 REAL GEOGRAPHY — counties that are actually the county

## Context

Owner critique of the live pre-alpha (2026-07-12): "the county isn't accurate
at all and the size isn't good." Root cause is architectural, not polish: the
engine deliberately uses only name/centroid/state/seed, so every county is a
small synthetic district board (~one neighborhood) with archetype flavor — a
toy that represents, not depicts. Fixing accuracy and scale requires REAL
public geography. Census TIGER/Line is public domain (same honesty class as
the population data already committed): county boundary polygons, real water
(AREAWATER/LINEARWATER), primary roads, and PLACE (real incorporated
towns/cities with real names + county seats). Using it makes "this is your
county's shape, these are its real towns and rivers" TRUE — an NS-4 upgrade.
Provider (Google) geometry stays banned; nothing changes there.

## The product shape after 0.78

- County view: the board IS the county — its real silhouette, real coastline/
  rivers/lakes, real primary highways, and its real towns as tappable named
  anchors (county seat marked). Scale finally reads county-sized.
- Town view: tapping a town zooms into the EXISTING archetype district
  engine, now anchored at a real place and honestly titled with the real
  town name ("Homestead — generated preview"). Urbanization tier can use the
  town's context; building-level detail remains clearly generated preview.
- Honesty line shifts UP: geometry/names real (census), building fabric
  generated — the PREVIEW ONLY strip copy updates to say exactly that.

## Owner decisions (2026-07-12)
- **AAA content pipeline**: deterministic BAKE (versioned packs = source of
  truth in repo/object storage) SERVED through the existing backend +
  scene-packet Redis cache. Repo holds the bake; runtime serves it. This is
  how a AAA studio ships world data: baked, versioned, streamed.
- **Max detail everywhere — via LOD streaming, not all-at-once**: ALL TIGER
  roads including local streets, delivered the AAA way: LOD0 county
  (shape/water/primary+secondary highways/towns) → LOD1 regional zoom
  (all secondary + major locals) → LOD2 town (full local streets + generated
  building fabric). This makes W6.1/6.2 (streaming windows + incremental
  rebuilds) a REQUIRED phase of this program, not deferred.

### 0.78-R — Renderer LOD + streaming (absorbs W6.1/6.2; prerequisite for max detail)
- Chunk-based scene windows keyed to camera (perf seat's design), incremental
  rebuilds (no full teardown on window crossings), LOD tiers per road class/
  detail layer. Gates: Graphics ≤1600 per window AT EVERY LOD, rebuild
  ≤350ms, zoom transition without hitching (measured in emulator perf).

### 0.78-D — Data pipeline (Fable/reviewer-run; network + big files)
- `scripts/build-county-geo-packs.mjs`: download TIGER 2024 (counties
  national boundary; per-state PLACE; per-county AREAWATER/LINEARWATER +
  PRIMARYROADS), simplify (Douglas-Peucker to a per-county vertex budget),
  emit compact per-county geo packs: boundary ring(s), water polys/lines,
  primary-road polylines, top-N places {name, lonlat, pop?, isSeat}.
  LOD-tiered packs: LOD0 ≤8KB (boundary/water/primary/towns) committed;
  LOD1/LOD2 road tiers baked to `data/geo-packs/` (size reported; if the
  full-street bake exceeds repo sanity ~150MB, LOD2 lives in object storage
  and is served via the backend cache — decision recorded in the packet).
  Shapefile parsing: prefer Census's own GeoJSON via TIGERweb REST if
  simpler; else add ONE build-time-only dep (e.g. shapefile) confined to the
  script (never shipped to widget). PR + AK edge cases validated explicitly.
- Gate: pack determinism (re-run byte-identical), coverage (3,222 packs),
  size budget, boundary sanity (area vs gazetteer ALAND within tolerance).

### 0.78-1 — County board = real silhouette (core engine)
- New compile path `compileCountyGeoScene(pack, facts)` in packages/core:
  voxelize boundary → board mask (terrain tiles clipped to county shape,
  existing tile/relief grammar inside), real water rendered from pack
  (reuse E3 water bands/strand styling), primary roads as polylines (reuse
  W4.2 road art profiles by class). Scale normalization: county longest
  axis → board budget; window budgets extended deliberately.
- Wire: `_meta.generatedDraftSpec` gains `geoPackRef`/inline pack (spec
  stays <15KB) — widget compiles client-side as today (0.76-T pattern).
- Gates: silhouette IoU ≥0.85 vs simplified source for 16-county challenge
  set; water/road presence truth-checks vs pack; Graphics/rebuild ceilings
  hold at county scale (this is THE perf risk — kill-criteria: if county
  boards can't hold 1600/350, reduce vertex budgets, never fake).

### 0.78-2 — Real towns as anchors (core + web)
- Places = pack places (REAL names, honest) as tappable anchors on the
  county board, seat highlighted; P1.1's interactivity (in flight) applies.
- ask_county_question routes through real towns ("where is Homestead?").
- Gate: every county ≥1 anchor (fallback: county seat = gazetteer name),
  full-index label honesty gate (P1.2's, retargeted to real names).

### 0.78-3 — Town detail = existing district engine, re-anchored (core)
- Tap town → generate the current archetype district FOR that town
  (seeded by county+town), titled with the real town name; tier from
  county facts (town pop when pack has it). Camera transition county↔town
  via existing preset machinery; widget state per scene id (P1.1's
  sceneSessions). Existing 158-check inspector extended with a
  county→town→county navigation cell.

### 0.78-4 — Copy + honesty re-line (web/server, small)
- PREVIEW ONLY strip: "Real county shape, towns, and water from the U.S.
  Census. Buildings are a generated preview." (plain words, no jargon).
- Landing page + tool descriptions updated to the now-true claims.
