# Product Metrics + Kill/Proceed Gate (0.78-R)

Status: NAMED WORK ITEM — thresholds not yet set (see §4). Program of record:
`.gstack/plan-zoom-band-lod.md`, decisions #19, #20, #40, #61. Companion to
`docs/0.78R_ROAD_ART_CONTRACT.md` — together the two documents ARE the

everything"). Road Art owns the identity verdict; this document owns the

authorized.

## 1. Why these four metrics, and why a gate at all

Premise-gate amendment to P2 (decision #19, owner call): the multi-GB
national-bake spend is no longer authorized on architecture conviction
alone. It requires product metrics with explicit kill/proceed thresholds,
evaluated BEFORE that spend — this is the mechanism that moved D3 national
behind the 6-county evidence gate (decision #20, superseding the same-day
ratified infra-first order). The plan names exactly four metrics: **zoom
depth, band dwell, drill-down rate, return sessions.** This document is
where those four get operational definitions (per decision #40 / codex-design
#6) and a gate structure — not a wishlist.

Per `docs/NORTH_STARS.md`'s spend rules, rule 4: "Kill-criteria in every
brief... written before launch — rejection is a normal, cheap outcome when
criteria exist." This document exists to make rejection possible, not to
justify a foregone conclusion.

## 2. The four metrics — operational definitions

### 2.1 Zoom depth

Deepest COMMITTED band reached per session (FAR / MID / NEAR), or the
session distribution across those three values.

- "Committed" means the band controller's committed state (decision #56 —
  band selection is stateful; hysteresis/latches live in a controller, not
  in `windowFor`), not the raw camera zoom scalar. A camera that crosses the
  0.7 or 1.4 threshold but parks there under hysteresis without the
  controller committing the new band has NOT reached that depth.
- Recorded once per session as the session's maximum, not per-frame.

### 2.2 Band dwell

Time spent at a committed band, per visit.

- The dwell timer **starts post-settle** — i.e., after the transition lands
  as the single transactional commit defined in
  `docs/0.78R_MOBILE_UX_A11Y.md` §2 (decision #58), not at gesture start and
  not at the first frame of the incoming band's construction.
- A **minimum dwell floor** applies before a visit counts at all — a
  commit immediately followed by a reversal (user overshoots, corrects) is
  transit, not a visit. The floor's exact duration is a threshold value (see
  §4), not a definitional question; the definitional question (dwell starts
  post-settle, requires a floor) is answered here.
- Ends at the next transition commit (band change in either direction) or
  session end, whichever comes first.

### 2.3 Drill-down rate

Sessions (or session-fraction) that execute a NEAR-entry via the Entry
affordance defined in `docs/0.78R_MOBILE_UX_A11Y.md` §1 — tap a town anchor,
or an intentional zoom past the NEAR threshold that reaches gesture settle.

- **Counted ONLY via the entry affordance.** A pinch or wheel gesture that
  crosses the NEAR threshold and settles there without going through either
  qualifying path is not currently expected by the plan's own contract (§1's
  two Entry paths ARE "intentional zoom past threshold" and "tap anchor") —
  in practice this means: settle at NEAR band = drill-down, by construction,
  since NEAR is defined as reachable only through those two intentional
  paths. The exclusion this operational definition actually enforces is §2.4
  below.
- This is the same event the NEAR product contract's Entry affordance
  produces — no separate instrumentation surface; do not build a second
  "did the user drill down" signal that can drift from what the UI contract
  calls Entry.

### 2.4 Accidental pinch crossings — excluded, not counted as anything

A pinch or wheel motion that crosses a band threshold (0.7 or 1.4) WITHOUT
the gesture reaching one of the settle conditions defined in decision #57
(wheel-idle, inertia end, cancel, lost pointer capture, blur, unmount) is
**not a band visit, not a drill-down, and does not start a dwell timer.**
This is threshold-parking territory (R1's hysteresis exists specifically to
prevent this from thrashing the renderer) and it must not thrash the METRIC
either. Only a controller-committed band change (§2.1) is a countable event
for any of the four metrics.

### 2.5 Return sessions

A session in which the user returns to a county or place they previously
visited.

- **Open definitional gap, flagged here rather than papered over:** "session"
  boundary is not self-evident in this architecture. Atlas has no
  persistent client session today (P2 persistence is separate, in-flight,
  server-side work) and MCP tool calls are the unit of interaction, not a
  stateful client session in the traditional web-analytics sense. Whether
  "return" means (a) same ChatGPT conversation, later turn, (b) a new
  conversation entirely, or (c) both counted separately with different
  weight, is NOT decided by the plan text and must be resolved as part of
  §4's threshold work, not assumed here.
- Whatever the boundary, the return event itself reuses the same "county or
  place previously visited" signal the NEAR product contract's Return step
  already produces (camera restore + kept pin) — this metric measures
  whether users independently choose to come back, not whether the Return
  control works (that's a UX correctness question, not a product metric).

## 3. Kill/proceed gate structure

Two-stage evaluation, per the plan text: "evaluated on the adversarial 6
(and on real usage once the flag lifts) BEFORE the national bake spend is
authorized."

**Stage A — adversarial-6 instrumented pass (the actual go/no-go gate).**
Runs the four metrics against real interaction traces on `miami-dade-fl`,
`loving-tx`, `apache-az`, `orleans-parish-la`, `sedgwick-ks`, `suffolk-ma`
(same six counties as the Road Art Contract's identity gate, evaluated
together). This is a small, deliberately adversarial, non-representative
sample by design (dense metro / sparse rural / huge western / water-heavy /
suburban grid / northeastern dense) — thresholds here are read as directional
signal, not a statistically powered study.

**Stage B — real-usage confirmation once the flag lifts.** Continuous
validation against the same four metrics once `?atlasGeoBoard=1` is no
longer required to see the feature.

**Flagged sequencing tension, resolved here for the record:** read literally,
the plan sentence could mean Stage B gates the national bake spend, not just
Stage A — but flag-flip to default-on is explicitly listed as **NOT in
scope** for this program (a separate owner gate, P6) and real usage cannot
exist before that flip. That would make the national-bake authorization
depend on a prerequisite the plan itself puts out of scope — a circular
requirement. The sensible reading, and the one this document adopts unless
the owner corrects it: **Stage A (adversarial-6) is the actual kill/proceed
gate for the national bake spend; Stage B is continuous post-lift validation
that can revise or reconfirm the call, not a blocking prerequisite for it.**
This should be confirmed explicitly at the next owner gate alongside the
threshold values in §4 — it is a real ambiguity in the ratified plan, not a
settled decision being restated.

**What this gate is NOT (decision #61):** the adversarial-6 evaluation is a
PRODUCT gate. It is explicitly not a national-operations proof — D3's
national-ops hardening list (pagination, checkpointing, bounded concurrency,
canaries) is a separate concern evaluated on its own terms before the
national bake runs, regardless of what the product metrics say. A clean
product-metric pass does not imply the bake pipeline is ready for 500x scale,
and a not-yet-hardened bake pipeline does not block evaluating product
metrics on the 6 counties, which only need the D3-lite shakedown bake.

## 5. Instrumentation dependencies (reuse, don't rebuild)

- Band-commit events: the band controller (decision #56) is the single
  source of truth for "committed band," used by zoom depth and dwell.
- Gesture-settle events: decision #57's settle definitions (wheel-idle,
  inertia end, cancel, lost capture, blur, unmount) are the single source of
  truth for excluding accidental crossings (§2.4).
- Entry-affordance events: `docs/0.78R_MOBILE_UX_A11Y.md` §1's NEAR Entry
  path is the single source for drill-down rate — do not instrument a
  second "reached NEAR" signal that can drift from the UI contract.
- Transition timing: the R3 instrumented trace / S8 band-transition timing
  telemetry is plumbing this document rides, not plumbing it re-specifies.
