# Plan: 0.80 Graphics Excellence + P2 Personal Atlas (save data)

## Context

Owner directive: make the graphics/labelling as high-quality as possible
(critical eye), and give Atlas a "service account so it can save data" so a
user's Atlas persists. Two programs, both grounded in first-hand review:

- **Graphics**: eyes-on critique of the live Miami-Dade generated preview
  found real defects — water is a flat pool with a hard diagonal edge (not a
  coastline), roads dominate the frame, the palette reads muted-generic (not
  tropical for FL), lighting is flat (no sunlit/shade pop), the board edge
  cuts abruptly, the top-right quadrant floats empty, and place labels are
  tiny/faint/single-tier (fontSize 10, alpha-0.34 backing, only priority≥9
  shown). The 0.79 visual-score gates *structure* but not *aesthetics* — a
  gap for a "high quality" bar.
- **Save data**: the persistence layer is ALREADY BUILT and dark behind
  flags — Postgres schema (`users` keyed on `oidc_subject`, all entities
  owner-scoped + cascade), repository, service, Stripe billing, OIDC bearer
  verification, REST plane `/api/hosted-clawd/*`. The ONLY missing piece is
  identity: the MCP call carries no stable ChatGPT user id; the sole stable
  key is an OIDC `sub`. The client already models the data
  (`WidgetState.sceneSessions` — per-chat pins/notes); making it survive
  across chats = an identity + moving that model server-side.

Owner decisions (2026-07-12): polish current engine now + real-geo pass
after; frictionless identity (OAuth invisible after one-time connect, since
no free id exists); v1 saves = Personal Atlas pins+notes per county;
labels = prominent, tiered, real names.

## Program A — 0.80 GRAPHICS EXCELLENCE (polish the current engine now)

Each item is a fenced codex packet; I crop-test every visual change; the
0.79 score + floors gate regressions; curated Riverside stays byte-identical.
PERF LAW (from the render map): every new stroke pass costs against the 1600
Graphics ceiling AND the 350ms rebuild budget, and the 0.79 median floor
(98.6) has NO headroom — so packets must NOT reduce palette-separation,
massing-distance, or opening-occupancy signals, and should buy richness by
(a) the global grade filter [free, one full-screen pass], (b) raising
alpha/contrast on EXISTING passes, or (c) retiring a cheap pass to fund a
better one — not by piling on new per-object passes.

Ordered cheapest-highest-leverage first:
- **0.80-1 Global grade + lighting** (renderer only, ~free): the whole-canvas
  grade filter (`CityWorldRenderer.tsx:334-385`) currently flattens to pastel
  (saturation 0.96, highlight compression) — loosen rolloff, lift saturation,
  strengthen split-tone. Then widen the 3-value box lighting spread
  (`sunlitColor`/`buildingFaceColor` :7389-7412): deeper/warmer shade,
  brighter sun, add ground-contact AO. This is the single biggest look win at
  near-zero object cost.
- **0.80-2 Water craft** (renderer :1661-1687): break the `variant%2` tiling
  highlight (continuous shimmer noise), animate terrain water alpha (today
  only sparse props animate), soften the shoreline with a graduated
  shallow-water band instead of the single hard strand. (Real coastline SHAPE
  comes from 0.78; this is the water *material*.)
- **0.80-3 Road recede + board lift** (renderer): reduce road dominance at
  the single knob `road.width * 15.2` (:2382) + per-tier `arterialWidth`
  (`cityWorldCountyParameters.ts:130-173`); add a board vignette / contact
  shadow to `drawBoardEdgeFade` (:1566) so the diorama lifts off the surround.
- **0.80-4 Regional palette vibrancy** (compiler): widen the "muted SoCal
  placeholder" ramps in `cityWorldRegionalPalettes.ts` + `resolveModulation`
  offsets (`cityWorldCountyParameters.ts:942-989`); give tropical its OWN
  palette/props rather than reusing river_town (0.77-2 is a thin overlay
  today). Must keep the palette-separation signal above floor.
- **0.80-5 Composition + focal hierarchy** (overview-focus scorer, already
  partly in 0.79-T/T2): one clear hero landmark anchors the frame; no empty
  quadrants at the opening camera.
- **0.80-6 Aesthetic score signals** (visual-score.mjs): add measurable
  proxies the current score lacks — lighting contrast, water animation
  presence, palette vibrancy range — so beauty gains are gated too, not just
  structure.

## Program C — P2 PERSONAL ATLAS (save data across chats)

The storage is built; this is identity + the personal-data tables + wiring.

- **C1 Identity via Apps SDK OAuth** (frictionless-after-connect): stand up
  an OIDC authorization server (Auth0-shaped, per the existing
  `docs/HOSTED_CLAWD_STORAGE_AUTH_DECISION_PACKET.md`); ChatGPT runs the
  authorize flow once when the user first saves (MCP `WWW-Authenticate`
  challenge already emitted by `auth.ts`); thereafter the bearer flows
  automatically. Seam already exists: `verifyBearerToken` →
  `upsertUserByOidcSubject`. HUMAN gates: Auth0 tenant setup, prod env
  (`ATLAS_OIDC_ISSUER/AUDIENCE/JWKS_URL`, `DATABASE_URL`,
  `ATLAS_HOSTED_CLAWD_PERSISTENCE_ENABLED=true`).
- **C2 Personal-atlas tables** (new migration `003_personal_atlas.sql`):
  `atlas_pins` and `atlas_notes`, owner-scoped (`owner_user_id` FK), keyed
  by `county_slug` + `place_id`, idempotent on `client_request_id` (reuse
  the existing `idempotency_keys` pattern). Mirrors
  `WidgetState.sceneSessions` exactly so the client model maps 1:1.
- **C3 Save/load wiring**: on save (authed), persist the county's pins/notes
  to Postgres; on county open, hydrate from Postgres into `widgetState` so
  the board shows the user's prior pins/notes. The save surface copy is
  already de-jargoned ("stays in this chat" → becomes "saved to your
  Atlas"); flip `ATLAS_SAVE_SURFACE` semantics for authed users.
- **C4 Honesty + safety**: session-only until authed (unchanged); authed =
  clearly "saved to your Atlas"; per-account rate limits (reuse W6.4 shared
  ledger); UGC/PII rules N/A for private personal data but privacy/terms
  updated to disclose account storage (HUMAN legal gate). This is the
  "Personal Atlas" layer of the P6 Commons vision — private branch first.
