# Road Art Contract (0.78-R / L1b)

Status: NAMED DELIVERABLE, owner eyes-on gate. Program of record:
`.gstack/plan-zoom-band-lod.md`, decisions #25, #37 (supersedes #25), #60.
This is a CONTRACT, not a style guide — an engineer who ships code that
satisfies a loose reading of "road-art grammar" while still producing GIS
polylines has failed this document, not satisfied it. That failure mode is
exactly why decision #37 replaced the earlier Road Art Spec.

## Why this document exists

Decision #37: "'grammar' was a pointer; an engineer could comply while
shipping GIS polylines" (Design Pass 4, codex-design #3). P5 is the
load-bearing product premise of the whole zoom-band program: "if roads read
as GIS, the program fails regardless of engineering quality" (CEO premise
challenge, 0A). This document is P5's enforcement mechanism for roads
specifically — L1b (MID highway styling) and L2a (NEAR street fabric) both
ship against it.

## 1. Grid quantization + permitted direction changes

- Every baked road segment snaps to the same iso-grid quantization the county
  board terrain already uses — no float-precision GIS vertices reach the
  renderer.
- Direction changes are limited to the permitted set already used by the
  generated-town road grammar (axis-aligned plus the diagonal set drawn by
  `drawRoadSegmentModule` / `drawRoadJointModule` in
  `web/src/CityWorldRenderer.tsx`). TIGER's arbitrary real-world bearings are
  resolved to this set at BAKE time, never smoothed or interpolated at render
  time.
- A road that would require an unpermitted direction change is either split
  into two permitted-direction runs joined by an authored module (§3), or
  simplified away (§2) — it is never rendered at its raw bearing.

## 2. Segment simplification + minimum visible run length

- TIGER geometry over-represents real curvature and survey jitter. Every
  segment is simplified (Douglas-Peucker or equivalent — the same family
  already used for county boundary/water in `build-county-geo-packs.mjs`) to
  the permitted-direction set in §1 before it is a candidate for rendering.
- A minimum visible run length is enforced PER CLASS (§4). Any simplified run
  shorter than its class's minimum is dropped outright, not rendered as a
  stub. This is the mechanism that keeps dense NEAR fabric from degrading
  into visual noise at authored-module density.
- Minimum run length is a bake-time constant, calibrated on the adversarial 6
  before the national bake. This contract fixes the RULE (simplify, then
  enforce a floor, then drop below it); the exact per-class number is a
  D1/L2a calibration output, not invented at review time.

## 3. Authored junction / ramp / bridge / dead-end modules — BAKED, not runtime

- Junctions, on/off ramps, bridges, and dead-ends render as AUTHORED MODULES:
  fixed voxel compositions keyed by topology type plus incident road classes
  — the same design language as today's `drawRoadJointModule` diamond
  intersection and `drawRoadEndCap` rounded dead-end cap, extended to cover
  ramp and bridge topology, which do not exist in the generated-town grammar
  yet.
- **Junction topology is computed at BAKE time and shipped as data. It is
  never recomputed at render time.** Today's runtime `collectRoadJoints`
  (`web/src/CityWorldRenderer.tsx:2740`) is an O(n²) pairwise-intersection
  scan over every visible road segment — cheap at generated-town scale
  (dozens of segments), NEAR-fatal at real-street-fabric scale. This is a
  code-verified eng-review finding (decision #60: "O(n²) joints NEAR-fatal").
  D1's bake pipeline computes joints once per county and ships junction
  records inside the pack; the NEAR renderer's perf gate benchmarks against
  max VISIBLE SEGMENT COUNT, never against a runtime pairwise-joint pass.
- A junction with no authored module for its topology+class combination does
  not fall back to a raw line-crossing. It resolves to the nearest defined
  module via a documented fallback table, or the segment is held back for a
  later bake pass. No junction ships un-authored.

## 4. Class hierarchy via width / elevation / edge treatment / value — NEVER color-only

Road class (interstate / primary / secondary / local, per D1's TIGER
class-tagging) is legible through STRUCTURE, not hue:

- **Width** — each class has a distinct rendered width band; interstate reads
  visibly wider than local at every zoom band it appears in.
- **Elevation** — grade separation (ramps, overpasses) renders with real
  z-offset and contact shadow, never a color swap standing in for "this road
  is above that one."
- **Edge treatment** — curb, shoulder, and median presence and weight differ
  by class (interstate gets shoulder + median treatment; local gets the
  plain curb/bed/surface layering `drawRoadSegmentModule` already draws).
- **Value** (light/dark relationship within the palette) is a secondary cue
  only, never the sole cue. This is the same rule the Accessibility contract
  states independently in `docs/0.78R_MOBILE_UX_A11Y.md` ("non-color class
  distinction") — color-blind legibility and GIS-avoidance are one
  requirement seen from two doctrines, and this contract and that one must
  never diverge on it.
- Class palette entries come from `atlas.manifest` (the existing asset-pack
  pattern), never hand-picked hex values inline in renderer code — this
  keeps road-class color themeable and auditable in the same place as
  terrain and water.
- New road-class palette entries are added to the existing 12-cell contrast
  audit matrix (decision #28) — both themes must hold contrast WITH roads
  present, not only with terrain.

## 5. Fixed density ceiling preserving terrain negative space

- Every band has a fixed maximum rendered-road density (segments, or
  linear-voxel-units, per chunk) independent of how much real TIGER data
  exists in that chunk. Dense-metro NEAR fabric does not get to fill the
  frame — terrain, lot, and building negative space stays visible even in
  Miami-Dade-density chunks. This is what keeps a "board," not a street
  atlas, on screen.
- The ceiling is enforced at bake/serve time. The 32KB warn / 64KB fail
  per-chunk byte ceiling (decision #45) is the STORAGE proxy; the density
  ceiling here is the VISUAL proxy, and is calibrated separately on the
  adversarial 6 before the national bake. This contract fixes that the
  ceiling exists and what it protects (terrain negative space); the exact
  per-band number is a D1/L2a calibration output.
- When real road density exceeds the ceiling, §6 decides what drops. The
  ceiling is never satisfied by shrinking or thinning roads below their
  class's authored treatment — thinner-but-still-everything is not a legal
  way to hit the ceiling.

## 6. Minor-road disappearance rules

- Roads DISAPPEAR outright when they don't fit the current band's ceiling.
  They never collapse into noise: no hairline degraded rendering, no
  color-only demotion, no "too small to read" stub.
- Disappearance is deterministic and class-ranked: local drops before
  secondary, secondary before primary, primary before interstate, at every
  ceiling breach. It is never random or viewport-jitter-dependent — two runs
  of the identical camera state must drop the identical roads.
- A dropped-but-real road reappears the moment its class's band is reached
  (MID → NEAR) or the ceiling gains headroom (an adjacent, less-dense chunk)
  — disappearance is a rendering decision, not data loss. The bake always
  retains the full class-tagged network per D1, regardless of what any given
  band chooses to render.
- Minimum visible run length (§2) and the density ceiling (§5) are the two
  independent triggers for disappearance; either alone can drop a segment.

## 7. Ban list

The following never ship, at any band, on any county:

- Smooth GIS strokes — anti-aliased polylines at raw TIGER bearing/curvature.
- Generic map casing — the black-outline-plus-fill-color styling associated
  with Google/OSM-style road casings.
- Label clutter — street names printed on or along the road itself. County
  name, town anchors, and the pinned/tapped place are the only text NEAR
  carries (see the NEAR product contract in `docs/0.78R_MOBILE_UX_A11Y.md`).
- Any per-segment color whose only job is to distinguish class (§4 — value is
  a secondary cue; structure is primary).
- A feathered or faded edge standing in for a hard boundary. The NEAR
  focus-radius edge is a hard, grid-aligned chunk boundary (decisions #23,
  #34), not a vignette.

## 8. Theme parity — "parity, not port"

Per decision #32: passing the contrast matrix in both themes is necessary but
not sufficient. Dark-theme road treatment must be its own authored pass — own
value relationships, own edge-treatment weight where needed — never the
light-theme art with colors inverted or an opacity multiplier applied.
Acceptance requires a reviewer to judge dark-theme MID/NEAR screenshots on
their own, independent of the light-theme set, and confirm they read as
authored rather than derived.

## 9. Acceptance protocol — the gate

Same-camera screenshot set required per adversarial-6 county (`miami-dade-fl`,
`loving-tx`, `apache-az`, `orleans-parish-la`, `sedgwick-ks`, `suffolk-ma`):

- FAR, MID, and NEAR bands.
- Desktop viewport AND `390x844` mobile viewport — the existing
  screenshot-evidence convention (see
  `docs/brain/ROAD_LOT_TERRAIN_CONTACT_GRAMMAR_SPEC.md`).
- Both themes (§8 requires independent dark-theme judgment).
- 6 counties × 3 bands × 2 viewports × 2 themes = 72 screenshots minimum for
  one gate pass.

Per-county owner verdict, recorded per county — not once for the set:

```
COUNTY               | VERDICT
----------------------|---------------------------------
miami-dade-fl         | "Atlas voxel board" / "generic map"
loving-tx             | "Atlas voxel board" / "generic map"
apache-az             | "Atlas voxel board" / "generic map"
orleans-parish-la     | "Atlas voxel board" / "generic map"
sedgwick-ks           | "Atlas voxel board" / "generic map"
suffolk-ma            | "Atlas voxel board" / "generic map"
```

**ANY single "generic map" verdict fails the gate.** No averaging, no
majority, no "5 of 6 is close enough." This is the same zero-tolerance
posture NS-4 (honesty) holds elsewhere: one wrong county proves the
architecture is wrong, not just an asset (decision #12: "one flagship can
hide a nationally wrong architecture"). A failed gate returns to §1–§7 for
rework — not to a re-shoot of the same art or a re-vote on the same
screenshots.

## 10. Explicitly open, not decided here

- Interstate highway shields as voxel signage at MID remain an OPEN taste
  decision, deferred to the identity verdict at the 6-county gate (Pass 7
  disposition: "DEFERRED, auto-revisits at the 6-county identity verdict").
  This contract does not presume an answer — §4's width/elevation/edge
  hierarchy must read as a complete class system WITHOUT shields, since
  shields may not ship.
- The settle micro-animation for band transitions carries a ZERO motion
  budget until R3 is trace-proven (decision #3). §3 and §6 above describe
  static authored appearance, not transition motion. What order chunks
  materialize in, and the rule that a transition is a single transactional
  commit rather than a visible batch sequence, is specified in
  `docs/0.78R_MOBILE_UX_A11Y.md`, not here — Road Art governs WHAT is drawn;
  Mobile UX / status rules governs WHEN it becomes visible.
