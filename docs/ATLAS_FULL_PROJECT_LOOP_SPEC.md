# Atlas Full Project Loop Spec

Atlas is a ChatGPT app that turns counties into explorable voxel worlds. The
loop exists to keep the project moving from public Alpha to Engine Beta, then to
second playable district, then to Hosted Clawd paid Beta without losing the
map-first product or faking coverage.

## Product Goal

Open ChatGPT, launch Atlas, and use a high-quality county world:

1. Play Riverside/Eastvale now.
2. Browse honest California shells.
3. Lookup real places without saving or claiming readiness.
4. Drop Clawd into a location.
5. Preview a scout and campaign.
6. Upgrade later to Hosted Clawd for saved memory, quests, evidence, XP, reports,
   and exports.

## July 4 Release Bias

Ship a credible public Alpha / Engine Beta proof before chasing full paid scope.
The release must be honest:

- one public playable district is acceptable if it feels serious;
- shell counties are acceptable if recovery is obvious;
- hidden Anaheim work is acceptable only as hidden readiness proof;
- paid/persistence claims are not acceptable until the backend is reopened and
  verified.

## Execution Spine

### Phase 1 - Public Alpha Baseline

Status: deployed and proven.

Must remain true:

- seven MCP tools unchanged;
- Riverside/Eastvale public playable;
- Orange/L0 honest recovery;
- Scout/Campaign session-only;
- no saves, XP, evidence, payment, posting, messaging, or automation.

### Phase 2 - Engine Beta Quality

Current active spine.

Goals:

- stronger terrain/world-edge massing;
- no repeated placeholder-block read;
- stronger civic/venue object grammar;
- mobile `390x844` readability;
- no cars, humans, decorative clutter, panels, or label crutches.

Loop rule:
Every visual/engine slice must name one measured axis before coding and report
before/after metrics after verification.

### Phase 3 - Second Playable District Readiness

Default candidate: Anaheim.
Control candidate: Ontario.

Promotion needs:

- source-noted anchor pack;
- hidden draft scene;
- no-label visual packet;
- Mira product proof;
- Forge split/provider proof;
- Axiom release cutline;
- public UI plan.

Current cutline:
`BLOCK_PROMOTION`.

No public Anaheim/Ontario switcher state is allowed until the cutline changes to
`APPROVE_CONTROLLED_PUBLIC_SPIKE`.

### Phase 4 - Consumer Save Layer

Only after Engine Beta and second-district proof are credible.

Build order:

1. typed session/save contract;
2. backend service seam;
3. auth boundary;
4. persisted Clawd state;
5. saved scout/campaign;
6. evidence/XP ledger.

No Stripe until persisted entitlement checks and webhook-backed plan state are
ready.

### Phase 5 - Hosted Clawd Paid Beta

Paid users hire Hosted Clawd Daemon.

Paid unlocks:

- saved business memory;
- saved campaigns;
- quests;
- evidence;
- XP/progress;
- weekly reports;
- exports.

Hard rule:
Checkout alone cannot grant product access. Stripe/webhooks must sync plan state
before persistent capabilities unlock.

### Phase 6 - USA-Scale Release

Scale through contracts, not fake rendering.

Hierarchy:
`country -> state -> county -> district -> place`.

Coverage tiers:

- `L0_UNSUPPORTED`
- `L1_COUNTY_SHELL`
- `L2_CURATED_DISTRICT`
- `L3_PROVIDER_NORMALIZED`
- `L4_PUBLIC_QUALITY`

Every county may be indexed, but only promoted counties become playable. The
renderer consumes bounded `CityWorldScene` slices only.

## Big 4 Artifact Roles

- Axiom: loop owner, architecture, release authority, final cutline.
- Mira: product/app artifact builder, mobile proof, ChatGPT tool language.
- Lumen: voxel-engine artifact builder, object kit, screenshot/metric quality.
- Forge: data/backend/release artifact builder, provider boundaries, split guard.

Each artifact packet must include:

- changed files;
- artifact built;
- verification;
- skipped scope;
- next artifact.

## Loop Readiness Levels

- L1 report: update state, run verifiers, no code.
- L2 assisted: implement bounded artifacts with verifier proof; no deploy without
  human gate.
- L3 unattended: not approved for Atlas yet.

Atlas is currently L2 assisted.
