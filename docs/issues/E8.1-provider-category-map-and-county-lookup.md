# E8.1 Provider Category Map + County Lookup Adapter

## Summary

Connect the USA-scale world API foundation to real provider normalization without changing the visible map UI.

E8.1 should make Google-derived places and location lookups flow into Atlas-owned categories, identities, source notes, and cache policy. The renderer must continue consuming `VoxelScene` and `CityWorldScene`, never provider payloads.

## Requirements

- Add provider-independent place category contracts for Atlas world data.
- Map Google Places API (New) place types into Atlas categories.
- Add county/city/district lookup contracts behind `GeoDataAdapter`.
- Preserve source notes, attribution fields, cache keys, and TTLs for provider-derived data.
- Keep the existing curated Riverside/Eastvale scaffold as fallback and test data.
- Keep Railway as the expected live deployment lane.

## Acceptance

1. Core world types can represent provider-independent place categories. Done.
2. Google-specific place types normalize before reaching `NationalWorldService` or renderer contracts. Done.
3. Unknown provider place types fall back to a safe generic category instead of breaking render compilation. Done.
4. County/district lookup contracts are typed and documented. Done.
5. Existing E8.0 world API routes keep working. Done locally and on Railway.
6. No raw Google payload reaches Pixi, React, `VoxelScene`, or `CityWorldScene`. Done.
7. No new dashboard UI, auth, persistence, Stripe, or national canvas is added. Done.

## Implemented Foundation

- Added `WorldPlaceCategory`, `WorldPlaceLookupResponse`, and lookup-safe place summary types in core world contracts.
- Added Google/mock place type normalization in `@atlas/geo`.
- Added `NationalWorldService.lookupPlaces`.
- Added `GET /api/world/lookup?query=Eastvale%2C%20CA&radiusMeters=3500`.

The route returns normalized Atlas category summaries, cache policy, source notes, and a resolved location summary. It does not compile a live `CityWorldScene` and does not expose raw provider fields to the renderer.
