# E8.4 ChatGPT App Review Polish + QA Harness

## Summary

Make Atlas submission-ready as a ChatGPT app by tightening the submission artifact, MCP verification, public preview checks, and review documentation.

This is a review/readiness pass. It must not change the product shape, add persistence, add campaign execution, or bring back dashboard/card UI.

## Acceptance

1. `chatgpt-app-submission.json` clearly describes the map-first product shape and Alpha limits. Done.
2. Submission includes a live lookup negative case for scraping, saving provider data, and mass outreach. Done.
3. `verify:submission` validates submission JSON, MCP tool annotations, output schemas, provider boundaries, `_meta.scene`, and manual Alpha guardrails. Done.
4. `verify:preview:http` validates public preview delivery and catches old dashboard/report shell copy in the served HTML. Done.
5. Browser QA verifies `/preview` renders a full-screen city map on desktop and mobile. Done locally and on Railway.
6. Local checks pass before Railway deploy. Done.
7. Railway deploy succeeds and public MCP/submission/preview checks pass. Done.

## Anti-Scope

- No new user-facing tool.
- No auth, persistence, database, Stripe, XP, posting, messaging, scraping, or campaign execution.
- No renderer redesign unless QA finds a concrete blocker.
- No raw provider payloads in frontend contracts.
