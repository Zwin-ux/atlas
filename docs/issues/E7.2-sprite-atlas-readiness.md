# E7.2 Sprite Atlas Readiness

## Summary

Make the current full-screen Pixi city map ready for real tile and sprite art
without changing the product shape. E7.2 should keep the Alpha map working with
code-generated primitives, but add the manifest, validation, resolver, and folder
structure needed to replace repeated map objects with sprites later.

This is a visual-engineering pass, not a backend or feature expansion pass.

## Product Constraints

- `/preview` still opens directly into the full-screen Eastvale city map.
- React remains tiny HUD only.
- Pixi owns terrain, roads, lots, buildings, props, actors, labels, pins,
  stickers, hover glow, selected rings, and ambient animation.
- The map must keep feeling like a playable city map.
- No card shell, topbar, sidebar, report panel, dashboard page, campaign flow, or
  tactical framing returns.

## Required Work

### 1. Core Atlas Manifest Contract

Add a typed atlas manifest contract in `@atlas/core`.

Expected file:

- `packages/core/src/voxel/cityWorldAtlas.ts`

Expected exports:

- `CityWorldAtlasManifest`
- `CityWorldAtlasSprite`
- `CityWorldAtlasTile`
- `CityWorldAtlasPalette`
- `CityWorldAtlasValidationResult`
- `validateCityWorldAtlasManifest`
- `validateCityWorldSceneAtlasKeys`

The validator must check:

- Manifest shape is internally consistent.
- Scene `spriteKey` values either exist in the manifest or are explicitly
  accepted as primitive fallback keys.
- Scene `paletteKey` values exist in the manifest.
- Required categories are represented: homes, shops, gym, apartments, civic,
  park, roads, water, trees, cars, walkers, Clawd, pins/stickers.

### 2. Asset Folder

Create the durable asset lane:

- `packages/assets/city-world/README.md`
- `packages/assets/city-world/atlas.manifest.json`
- optional `packages/assets/city-world/textures/atlas-placeholder.png`
- optional `packages/assets/city-world/source/notes.md`

The first manifest may be fallback-first. It must still define stable keys,
palettes, anchors, tags, and fallback kinds.

### 3. Scene Metadata Tightening

Audit `compileCityWorldScene` output so the Eastvale scene has deterministic
metadata:

- terrain and road objects have stable tile/sprite keys where relevant
- lots have palette keys
- buildings have `spriteKey`, `paletteKey`, `roofShape`, `facadeStyle`, and
  `detailLevel`
- props have `spriteKey`, `paletteKey`, and `detailLevel`
- actors have `spriteKey`, `paletteKey`, and `detailLevel`
- pins/stickers have marker sprite keys

Do not add raw Google or provider fields to `CityWorldScene`.

### 4. Renderer Resolver

Add a small atlas resolver in the web and widget renderers.

Expected files:

- `web/src/cityWorldAtlasResolver.ts`
- `apps/widget/src/cityWorldAtlasResolver.ts`

Resolver behavior:

- Resolve `spriteKey` to a texture-backed sprite when a texture exists.
- Resolve `paletteKey` to fallback colors.
- Return a typed primitive fallback when texture art is unavailable.
- Never blank the map because an asset is missing.
- Keep missing-key warnings developer-facing, not visible as HUD panels.

### 5. Renderer Adoption

Move object drawing through the resolver in this order:

1. buildings
2. props
3. actors
4. markers
5. road details and water details if time allows

Keep the current primitive drawing helpers as the fallback path.

### 6. Visible Quality Improvement

E7.2 should include at least one noticeable map improvement even if most entries
are still primitive-backed. Good candidates:

- sharper pin/sticker marker art
- cleaner shop signs
- better tree silhouettes
- more readable car bodies
- improved crosswalk/curb details

Do not spend the whole pass on invisible plumbing.

## Acceptance

1. `CityWorldAtlasManifest` and validation helpers exist and are exported.
2. `packages/assets/city-world/atlas.manifest.json` exists and validates.
3. Current Eastvale `CityWorldScene` atlas keys validate against the manifest.
4. Renderer uses an atlas resolver for at least buildings, props, actors, and
   markers.
5. Missing textures fall back to existing Pixi primitive art.
6. `/preview` still shows one full-screen city map.
7. Drag, wheel zoom, pinch zoom, hover, place click, sticker drop, and note save
   still work.
8. Desktop and mobile browser QA show a dense nonblank city with no horizontal
   overflow.
9. No visible old language appears: `campaign`, `report`, `signal`, `risk`,
   `tactical`, `dashboard`, `board`.
10. No raw provider fields reach Pixi, React, `VoxelScene`, or `CityWorldScene`.

## Implementation Notes

Do not overbuild a custom asset pipeline yet. The key move is to make renderer
objects resolve through a stable manifest contract with graceful fallback. A
simple JSON manifest plus tests is enough for this slice.
