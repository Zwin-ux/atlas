# E7.3 Browser QA And Interaction Hardening

## Summary

Prove the post-atlas-resolver city map in a real browser and harden only the
smallest interaction defects found. This is a verification and polish lane, not
a redesign.

## Product Constraints

- `/preview` opens directly into the full-screen Eastvale city map.
- Pixi owns the map.
- React remains small HUD overlays only.
- No dashboard, report, campaign, tactical, card shell, or generic SaaS framing.

## Anti-Scope

- No Three.js.
- No auth, Stripe, persistence, evidence, or XP.
- No live county ingestion.
- No broad e2e suite.
- No provider payloads in renderers.
- No deploy unless a local release blocker is fixed and explicitly requested.

## Acceptance

1. Desktop preview loads one full-screen Pixi canvas.
2. Canvas is dense and nonblank.
3. Mobile `390x844` has no horizontal overflow.
4. Drag changes camera position.
5. Wheel zoom changes scale.
6. Place clicks work for Eastvale Core, Gym, Community Park, and Apartments.
7. Sticker drop works.
8. Note save works.
9. Console has no resolver or renderer warnings/errors.
10. No old visible language appears: `campaign`, `report`, `signal`, `risk`,
    `tactical`, `dashboard`, `board`.

## Verification

Run:

```powershell
pnpm verify:preview:http
```

Then use browser automation for desktop and mobile interaction checks when the
browser lane is available.
