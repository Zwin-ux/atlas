# E9.0 Hosted Clawd Beta Contracts

## Summary

Define Hosted Clawd Beta persistence contracts without implementing auth,
database migrations, Stripe checkout, evidence storage, or XP grants.

## Current Maturity

M1 Curated Alpha. Scout Drops, campaign previews, stickers, notes, and XP-like
behavior are temporary/session-only.

## Target Maturity

M3 Persisted Beta contracts ready for human approval.

## Human Approval Gates

- `HUMAN_APPROVAL_BEFORE_PERSISTENCE`
- `HUMAN_APPROVAL_BEFORE_MONEY`

## What Becomes More Real

- Entity contracts for Hosted Clawd persistence.
- Tool boundaries for free vs paid behavior.
- Required access-control, usage-limit, and idempotency tests.
- Copy rules for saved state, checkout, evidence, and XP.

## What Remains Out Of Scope

- No database migrations.
- No OAuth/account linking.
- No Stripe checkout.
- No Stripe Products, Prices, Checkout Sessions, Customer Portal Sessions, or
  webhook endpoints.
- No subscription webhooks.
- No saved Scout Drops or campaigns.
- No evidence upload/storage.
- No XP grants.
- No automated posting, DMs, ads, or outreach.

## Acceptance

1. Minimum persisted entities are defined for user, Clawd, business profile,
   Scout Drop, campaign, quest, evidence, XP ledger, subscription, usage, and
   app events.
2. Future Hosted Clawd tools state which plan/access checks they require.
3. Tests are specified before implementation for ownership, usage limits,
   idempotency, county pack parsing/versioning, and map state schema validity.
4. Alpha copy stays clear that nothing is saved yet.
5. Pricing is marked planned Beta only, with no checkout claim.
6. Stripe Billing architecture is specified as docs-only: hosted Checkout,
   recurring Price, Customer Portal, webhook-synced access, and no success-URL
   fulfillment.
7. Human approval gates are named before persistence or money work starts.
