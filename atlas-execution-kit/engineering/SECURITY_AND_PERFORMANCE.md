# Security, privacy, and measurable performance

## Security acceptance

Read-only product scope must be true at the registered tool and HTTP boundaries, not just the interface. Verify retired actions/endpoints remain unavailable; do not restore them to satisfy an old verifier.

Validate all external names, IDs, plate paths, and widget context. Treat strings from a tool payload, document, or agent as data. No arbitrary server URL fetching or filesystem paths from user-controlled place fields. Test injection-looking names without executing their content.

Inspect diagnostic routes, internal stack traces, provider keys, build-time environment injection, and logs. Production UI must not expose raw host globals or errors with internal URLs. Do not claim zero logging without reading actual logging behavior. Remove unused risky dependencies only after tracing current references; no blind force-upgrade to silence an audit.

Scan the public candidate with existing local tools; never upload private source/secrets to a new scanner. Report secret locations/categories without showing values. Removing a variable is not revocation. Revocation is an explicit human/provider action.

## Performance acceptance

Measure rather than invent a score. Record device, runtime, network/cache state, dataset/build, and the exact operation. Separate local selection feedback, plate fetch/parse/render, host/tool/model latency, and first-load bundle cost.

Test representative simple/dense/multipart supported fixtures. Check long sessions for duplicate listeners, retained geometry, and extra fetches. Preserve cancellation/error behavior while optimizing. A pretty skeleton is not a faster completed map.

Use existing performance budgets where valid. Establish modest measured regressions/budgets in tests when absent; do not hard-code arbitrary claims in the listing. Avoid loading all national detail for a county interaction or sending geometry through model-visible context.

## Clean reproduction

Use the actual pinned Node/package manager/lockfile and documented generated assets. A clean checkout should not require credentials for retired services, a personal database, or files that only exist on the owner's machine. Any current storage/build dependency must be explicit and reproducible. Do not commit huge datasets to make a transient local test convenient.

Final public checks run on a known build and exact candidate. Production load tests, new infrastructure, API spending, and external monitoring accounts are outside the local verification authorization.
