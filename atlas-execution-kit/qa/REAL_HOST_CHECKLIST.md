# Actual ChatGPT-host proof / cannot be replaced by preview

## Record first

Exact frozen candidate/build reference, service target, timestamp, client/platform, connection refresh steps, permitted account/session, and which acceptance cases are being run. Do not include account credentials, tokens, unrelated conversation history, or unconsented recordings.

Use current official host/testing documentation. If UI/resource metadata changed, refresh the connection as required and use a fresh conversation so a cached template is not mistaken for the new bundle. Preview/HTTP checks provide useful preconditions, not this proof.

## Run

- Open a reviewed named place directly; compare model answer, structured identity, displayed map and title.
- Enter the supported larger mode and return; verify the native composer and phone safe areas.
- Select a different supported feature. Confirm no chat message occurred solely from selection.
- Use the named follow-up action, then a supported contextual question. Confirm the current selection—not the initial place—is the subject.
- Test missing/stale context through the explicit named fallback or honest clarification.
- Request an ambiguous name; choose a real candidate and continue. Confirm prior correct map did not become falsely labelled.
- Induce or observe a safe retryable failure in the appropriate test target; confirm last-good-view recovery.
- Verify parent versus back behavior, keyboard/touch accessibility and another widget instance where supported.
- Test an unsupported directions/weather/business request; the app must not invent data or intercept unrelated tasks.

Inspect both the actual rendered component and model-readable result. Record each outcome and artifact, not just a screenshot of a successful prompt. If a client or capability cannot be accessed, list it as BLOCKED/NOT_RUN.

## After authorized deployment

Repeat the key initial/selection-follow-up/refusal flows against the deployed artifact. Local success does not establish that resource versioning, CSP or target configuration survived deployment. A portal challenge token is a separate owner process; never invent it.
