# Questions the final reviewer should try to break

Could an ambiguous result display the national map as a success? Can old metadata override a new refusal? Can the old map wear the new place's title? Can a slow request overwrite a newer choice? Does a delayed inspector action ask about an old feature? Can two widget instances confuse the question subject?

Do positive supported queries still succeed, or was refusal used to game correctness? Are a point and a boundary confused? Are missing values zero-filled? Is “largest” supported by ordering and completeness? Are unique county memberships asserted beyond the source representation?

Does a direct county open have a parent even without history? Does Back actually mean previous view? Does fullscreen remount duplicate a message? Does normal conversation scrolling unexpectedly move the map? Are labels usable on phone and keyboard? Does an agent action steal focus?

Is actual runtime behavior behind the screenshots? Was the native host checked on this exact candidate? Could cached templates make an old bundle look like the new build? Do code, model output, geometry and visible title refer to the same identity?

Are removed features still reachable through HTTP? Are diagnostics or internal URLs exposed? Did a dependency audit get silenced by removing checks or blind upgrades? Did another worker's changes get committed without attribution? Are secrets or private user test materials about to enter a public repo?

Are receipts tied to real artifacts and the integrated revision? Was the reviewer the implementation author? Did a local control gate get called full release approval? Was a submission acknowledgement called external approval? Are blocked permissions being silently bypassed?

For every confirmed defect, record a reproduction, affected acceptance IDs and a narrow repair. Do not hold the release for unrelated style preferences or speculative feature ideas. Reopen the correct graph node rather than proposing a new application.
